# 默认产出三份产物，执行过程零交互

一次整理默认产出三份产物（`00_handoff.md` + `01_conclusions.md` + `02_raw_log.md`），交接文档不再"用户选择才产出"，而是**默认生成**——仅当用户在触发指令中**明确申明不生成交接文档**时才跳过；主题切分与交接选择都不再回到用户之间确认，**执行全程零交互**（模型触发→切分→落盘→一行汇报，一气呵成）。这是对 v3.x「交接默认不产出、落盘前须询问」的**显式反转**：ADR-0002 确立的「只引用净结论、每个归档批次最多一份」**保留**；被推翻的「不得默认产出」「接交流须在落盘前询问」来自 `SKILL.md`「动作二」与 `references/design.md`「确认流程」的操作文本，而非 ADR——`references/design.md` 的「确认流程」整节随之废除。这样改是因为高频实跑（45 分钟内触发 4+ 次）已经证明"落盘前确认"的两问——切分方案与是否交接——几乎总是被原样接受，付出的交互成本换来的是用不到的二次确认；同时每次都问，反而把执行过程变成一段"为完成归档而进行的对话"，那段对话恰恰是 `技能痕迹` 判据要剔掉的东西（见 ADR-0006）。代价是交接文档偶尔会在用户没想要的时候多出一份（可事后删除，且触发时一句话即可跳过），以及用户想微调切分方案时不再有确认点——但切分本就属模型判断、无算法可校验，本就无可确认的确定性。版本从 3.1.0 升到 **4.0.0**：行为契约破坏性变更，与 ADR-0005 判 2.0.0、3.0.0 因"流水语义边界变化"判 major 的先例一致。

## 主题切分的余留（本条一并锁定，见 `references/design.md`「主题切分」）

- 范围仍可被用户圈定（默认整场）；圈定后主题切分**由模型自理，不回确认**。
- 用户可**可选**指定 1..N 个主题作**锚点**（可带一句范围描述作归类权重）。模型把能归入锚点的内容归入对应主题；不属于任何锚点的内容由模型自行归纳主题补足。
- 主题编号**按内容首次出现顺序**统一排：锚点只提供标签，不决定输出顺序（编号规则见 ADR-0001，主题仍是文件内二级标题）。
- 用户点名但对话内没有对应内容的主题**保留为空**，正文写 `（本主题无净结论）`——用户点了名就得给位置，与 `output-format.md` 既有的"成立但无净结论的主题保留标题"同一条逻辑。
