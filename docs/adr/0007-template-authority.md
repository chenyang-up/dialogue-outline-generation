# 磁盘模板是唯一的格式权威

每次执行前必须重新读取三份模板与 `references/output-format.md`，并且明确：同对话内已有的历史产物、模型记忆中的旧版本，都**不构成格式依据**；配套的兜底是落盘前按 `output-format.md` 的校验要点自检，不合规就修正后再落盘。这条规则来自一次实测的**静默漂移**——模板在 16:09:35 更新并重装，16:10:53 的那次执行却仍产出被废弃的旧格式，而 16:13:11 因为真的读取了模板文件，格式才正确；两批产物外观都完全正常，只有对照模板才看得出用了废弃格式。原因是格式契约只存在于模板里，而"按需加载"的文件在长对话中会**输给已经躺在上下文里的先例**：模型沿用了同对话前几批产物的形态，而不是磁盘上的现行模板。随后在独立样本上拿到了更强的证据：一场在技能换版前就已开始的对话，换版后再次调用，三份产物**完全没有**新版才加入的 `**技能版本**` 字段、也**没有**剔除技能痕迹——说明这条机制有个够不到的盲区：**已在进行的对话，其上下文里的技能内容是旧版，而新规则恰好写在它看不到的新 `SKILL.md` 里**，形成死结。代价是每次执行固定多出几次文件读取，`SKILL.md` 正文多了一段看起来冗余的强制指令——它正是用来压住上述先例的，**不要"优化"掉**；`执行前置` 里那条版本一致性自检只对载入新版之后的对话生效，因此**"改完技能必须新开一场对话再调用"是使用层的硬要求**，写进了 `README.md` 安装节。
