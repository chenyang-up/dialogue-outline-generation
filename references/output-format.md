# 产物结构规范

## 目录结构

```
<目标根目录>/dialogue-generation-file/
└── <归档批次：YYYYMMDD-HHMMSS>/
    ├── 00_handoff.md        # 交接文档（仅当用户选择交接时产出）
    ├── 01_conclusions.md    # 净结论
    └── 02_raw_log.md        # 问答流水
```

- `<目标根目录>` 默认是 `~/Desktop`，因此默认落盘位置为 `~/Desktop/dialogue-generation-file/`。注意只有**一层** `dialogue-generation-file`。
- 每个归档批次一个目录，编号 `00` / `01` / `02` 固定，不重命名、不调序。

## 三个文件的职责边界

| 文件 | 职责 | 消费者 | 是否可能缺席 |
|---|---|---|---|
| `02_raw_log.md` | 保留对话正文的**文字**（剔除框架噪音与技能痕迹）；标记按嵌套规则处理 | 人，用于回溯 | 否 |
| `01_conclusions.md` | 提炼净结论，按主题分节，节内按内容类型分四类 | 人 + 交接文档 | 否 |
| `00_handoff.md` | 只引用净结论，供下游接续 | 下游 agent | 否（除非用户明确申明） |

`00_handoff.md` **默认生成**（= 批次三份齐备），仅在用户触发指令中**明确申明不生成交接文档**时缺席，其余时候不得缺失。**三份产物均不含技能痕迹**（见 `design.md`）。

## 头部元信息

三份文件的头部固定为三行：

```
**对话**：<对话标题>
**归档批次**：<YYYYMMDD-HHMMSS>
**技能版本**：<本技能 frontmatter 的 version>
```

`**技能版本**` 是该批产物由哪一版技能生成的指纹，用于事后判断格式来源；须与 `SKILL.md` 的 `version` 一致。

## 主题分节规则

- 主题是**二级标题**：`## 主题 N：<主题名>`。
- `01_conclusions.md` 与 `02_raw_log.md` 的**主题编号与名称必须一致**，两份文件可互相索引。
- `00_handoff.md` 的「主题索引」表引用同一套编号与名称。
- 单主题时同样使用主题节结构，不切换到另一种形态。
- 主题层形状始终一致：**即使某主题没有任何净结论，也保留 `## 主题 N：<主题名>`，正文写 `（本主题无净结论）`**。原因是主题编号被交接文档的「主题索引」引用，跳号会破坏引用。判据是"**没有任何条目**"，统计时不区分条目是否带 `[未决]` 标记。
- **被技能痕迹剔空的主题不保留**：某主题的内容全部是技能痕迹时，该主题在流水与净结论中**一起消失**，后续主题**编号重排**、不留空号（见 `design.md`）。这与上一条不冲突——上一条说的是"主题成立但没有净结论"，本条说的是"主题根本不成立"。重排后两份文件的编号仍一一对应，交接文档的主题索引是同批生成的，跟着走即可。

## 净结论分类规则

- 净结论按**内容类型**分四类，顺序固定为「事实 → 决策 → 约束 → 待办」，用三级标题承载：`### 事实`、`### 决策`、`### 约束`、`### 待办`。
- 类别标题**按需保留**：某类别在本主题下没有条目时，不写该标题。不得出现有标题无条目的空类别标题。
- **未决项不是类别**，而是在条目行首加 `[未决]` 标记，形如 `- [未决] 是否要支持追加到旧批次`，可出现在任意类别下。
- 分类口径与判定问句见 `design.md` 的「净结论分类」一节；模板 `01_conclusions.template.md` 顶部也有同口径注释。

## 交接文档的小节

`00_handoff.md` 固定含以下小节，顺序固定：

| 小节 | 内容来源 |
|---|---|
| `## 目标` | 当前对话要达成的目标 |
| `## 主题索引` | 表：`#` / 主题 / 涵盖范围 / 净结论出处（指向 `01_conclusions.md` 的主题节） |
| `## 净结论摘要` | 按主题分节摘录 `01_conclusions.md`，**只含已落定条目**；不镜像四个类别标题 |
| `## 阻塞与未决` | **聚合全部 `[未决]` 条目**，每条标注来源主题与所属类别 |
| `## 推荐下一步` | 取自各主题「待办」类的条目，不得在此新增净结论里没有的动作 |
| `## 相关文档` | 指向同批次的 `01_conclusions.md` 与 `02_raw_log.md` |

**去重规则**：`[未决]` 条目**只出现在「阻塞与未决」**，不在「净结论摘要」里重复出现。

## 命名规则

- 归档批次目录：`YYYYMMDD-HHMMSS`，例如 `20260923-133100`。
- 文件固定三名，不加前缀后缀、不加主题名。主题信息只体现在文件内部，不体现在文件名上——这一点由 ADR-0001 决定。

## 校验要点

产物的结构契约（可用于验收）：

- 批次目录存在，且名称符合 `YYYYMMDD-HHMMSS`。
- `01_conclusions.md` 与 `02_raw_log.md` 均存在。
- 两者都至少含一个二级标题，且主题编号与名称一一对应。
- `01_conclusions.md` 每个主题节要么至少含一个有内容的类别标题，要么正文为 `（本主题无净结论）`。
- `01_conclusions.md` 中出现的类别标题顺序，若同时存在多个，须符合「事实 → 决策 → 约束 → 待办」。
- `[未决]` 只作为条目行首标记出现，不作为标题。
- `00_handoff.md` 最多一份；存在时不包含流水全文。
- `00_handoff.md` 的「阻塞与未决」与「推荐下一步」中的条目，均可在 `01_conclusions.md` 中找到出处。
- 三份产物都不含**技能痕迹**：没有本技能的触发指令、没有落盘回执、没有自检结论。
- 三份产物的头部均含 `**技能版本**`，且与 `SKILL.md` 的 `version` 一致。
- `02_raw_log.md` 中 `^#{1,3} ` 的命中行**只能是三类**：`# 问答流水（raw log）`、`## 主题 N：<主题名>`、`### 🧑‍💻 用户` / `### 🤖 模型`。轮次内容中的标题一律 ≥4 级——这条能机械核对，是防止内容标题污染文档大纲的红线。
- 轮次内容中的标题按**本轮偏移量**落级：偏移量 = `4 − 本轮内容最浅标题层级`；最浅一级落在 `####`；偏移后超过 6 级的封顶到 `######`（见 `design.md`）。
- `02_raw_log.md` 的围栏代码块之外，不存在未转义的行首 `---` 或 `===`。
