# 设计决策与边界规则

本文件收纳本技能已锁定的决策与边界规则。`SKILL.md` 只保留执行骨架，细节在此。

## 两个动作

- **整理是必选动作**。交接是可选动作，是否产出在**落盘前的那一次交互**中一并询问（见「确认流程」），不得默认产出，也不得静默跳过询问。
- 交接文档**只引用净结论**，不含流水全文。理由：下游 agent 的上下文预算有限，流水全文会挤掉真正有用的信息。

## 主题切分

- **主题是文件内部的二级标题，不产生独立文件**。这是本技能最容易被误读的一条：当两个主题之间明确无逻辑关联时，是在同一个文件里另起一个主题节，而不是另建一个文档。
- **不设单文件字符上限硬兜底**。允许单个文档很长，接受由此带来的体积代价，换取语义完整性。
- 切分依据是语义相关性，由模型判断，**没有确定性算法**。因此切分结果不进入断言，只对产物结构做校验。

## 净结论分类

- 分类轴是**内容类型**，四类，顺序固定：`事实 → 决策 → 约束 → 待办`。顺序按逻辑依赖排——先说事实，再谈由事实导出的决策与约束，最后是待办。
- **「未决」是条目标记，不是类别**（行首 `[未决]`），可出现在任意类别下。之所以不把它做成类别：它描述的是"落定没落定"，属于**状态轴**，与内容类型轴正交；强行平级会让同一条信息在归属上二义。
- **判定问句**：
  - 事实 vs 约束——「这条是**查到的**还是**约定的**？」查到的 → 事实。
  - 决策 vs 约束——「**换个场景这条还成立吗？**」成立 → 约束；只针对当时那个问题 → 决策。
- **归入优先规则**：「跨类都拿不准时，**归入它一旦落定后所属的类别**」。这条是本分类能自洽的关键——没有它，悬而未决的**选择**（如"是否要支持追加到旧批次"）会被图省事地塞进「待办」，使该类退化成第二个"未决类"。按本规则，它一旦落定是"支持/不支持"的一次性选择，故归 `决策` + `[未决]`。
- **两级保留策略**：类别标题**按需保留**（无条目就不写）；主题标题**始终保留**（该主题无任何净结论时保留标题、正文写 `（本主题无净结论）`）。**唯一例外**是被技能痕迹剔空的主题——它不是"无净结论"，而是根本不成其为主题，见「技能痕迹剔除」。
- **空主题判据**：以"没有任何条目"为准，**统计时不区分条目是否带 `[未决]`**。

## 框架噪音清单

流水要"逐字保留对话正文"，但"对话"只指对话双方产生的内容。以下边界是锁定的。另有两处要注意：一类要剔除的内容**来自对话双方**——技能痕迹，单独成节（见下）；另一处是**标记层级**的处理，也单独成节（"逐字"的确切范围在那里）。

### 剔除

- `<system-reminder>` 块（记忆与技能提醒、连接器状态、当前时间等）。
- 框架注入块：`<user-context>`、`<manually_attached_skills>`、`<project_context>`、`<team-project-context>` 等。
- 工具调用的机械返回，例如整份文件内容、目录列表。
- **模型的内部推理（thinking）**：它不是对话双方的输出，且原文通常冗长。

### 保留

- 用户消息全文。
- 模型正文全文，含代码块。
- **承载结论的工具结果退化为摘要保留**，例如构建报错、hook 失败原因、关键文件内容。这类信息往往正是本次对话的净结论所在，整体剔除会丢信息；原样保留又过于冗长，因此取摘要。

## 技能痕迹剔除

上面那节的判据是"**不是**对话双方产生的"；本节要剔除的内容恰恰**是**双方产生的，因此单列，不并入框架噪音。

- **判据有且唯一**：内容是否由「**使用本技能**」这一动作产生。触发指令、模型的执行过程与落盘回执、用户为完成本次归档所作的交互回答——这些是**技能痕迹**，一律不入产物。
- **两类容易误伤的内容，明确保留**：**关于本技能的讨论**（比如一场专门讨论归档设计该怎么改的对话）不是技能痕迹；**其他技能的使用**（比如本场同时用了别的技能）也不是，逐字保留。
- **三份产物一致**：流水、净结论、交接文档同样剔除。因此产物里不会出现"本次落盘到某路径""自检通过"这类只服务于归档动作的信息。
- **混合轮按内容拆分**：一轮里既有痕迹又有实质内容时（例如用户说「按 3 个主题整理；另外 X 项目下周上线」），剔掉服务归档的部分，保留与归档无关的实质内容。**不整轮丢弃**——整轮丢弃会制造"用户明明说了却被删"的不可预期缺口。拆分点由模型判断，与主题切分同理，接受主观误差。
- **变空的主题随之消失**：某主题的内容被剔除后不剩任何东西时，该主题在流水与净结论中**一起消失**，后续主题编号**重排**、不留空号。注意它**不是**"无净结论的主题"（后者保留标题、正文写 `（本主题无净结论）`），而是**根本不成其为主题**。
- **不留占位行**：剔除是静默的，不在流水里写「此处省略一次归档执行」之类的痕迹线。
- **整场被剔空则拒绝归档**：整场对话除技能使用外没有其他内容时，**不建批次目录、不写任何文件**，并明确告知用户原因；**不得静默地什么都不做**。这是本技能唯一可能出现"零产出"的情形。

## 轮次内容的标记嵌套

流水要把双方的原文填进模板骨架，而原文自身可能带标题、分隔线——这些标记会跟文件自己的三级标题打架，把内容里的 `##` 认成新主题、`###` 认成新轮次。规则锁定如下，**只作用于 `02_raw_log.md` 的轮次内容**（净结论与交接文档是提炼产物，不嵌入原文）。

- **本文件自己占三级**：`#` 文档标题 / `## 主题 N` / `### 🧑‍💻 用户`、`### 🤖 模型`。因此轮次内容里的标题必须落在 **4 级及以下**。
- **偏移量按本轮实际层级反推，而不是固定下沉三级**：设该轮内容里**最浅**的标题层级为 `m`，偏移量 = `4 − m`，用户与模型两侧统一。

  | 本轮最浅层级 `m` | 偏移量 | 效果 |
  |---|---|---|
  | `#` | +3 | `#`→`####`、`##`→`#####`、`###`→`######` |
  | `##` | +2 | `##`→`####`、`###`→`#####`、`####`→`######` |
  | `###` | +1 | `###`→`####`、`####`→`#####`、`#####`→`######` |
  | `####` 或更深 | ≤ 0 | 删掉多余的 `#`，把最浅一级提到 `####`（`#####`→`####`、`######`→`#####`） |

  三条理由：① **把 6 级预算用满**——固定下沉三级在原文最浅是 `##` 时会白白浪费一级，让本来放得下的内容提前溢出；② **跨轮一致**——每轮内容的最浅标题都落在 `####`，不会出现同一份文件里同级内容落在不同级别；③ **只有真实溢出才压平**。代价是同一份文件里不同轮次的偏移量可能不同（基准是各轮自己的层级），但读者是逐轮读的，不影响理解。
- **偏移后超过 6 级的封顶到 `######`**（Markdown 没有第 7 级）。这是**唯一**会压平的情形，且只在原文用到 4 个及以上层级时发生——那时在同一份文件里"既保住大纲、又保住全部层级"是不可能的，两害相权取"结构正确、深层压平"。因此本规则保证的是：**原文用 1–3 个层级时完全正确；4 个及以上时结构仍正确，最深的那一两级压平**。
- **围栏代码块之内原样不动**：用三重反引号或 `~~~` 包裹的内容里，行首的 `#` 不是标题，一律不改。无差别替换会**静默损坏代码**，比原问题更糟。
- **行首 `---` 与 `===` 转义为 `\---` 与 `\===`**：围栏之外、处于行首的分隔线若紧跟正文行，会触发 setext 标题，把上面那行正文变成二级标题，主题结构同样被破。转义后渲染仍是 `---`，但不再参与文档大纲。中间有空行、只当 `<hr>` 用的分隔线**一并转义**——不为"上面有没有空行"再做区分，规则越少越不容易出错。
- **其余标记原样保留**：粗体、列表、表格、行内代码、链接等一概不动。
- **改写必须可解释**：流水尾注须声明"文字逐字保留、标记按嵌套规则处理"。读者看到的层级已经不是原文的样子，产物自己得能解释为什么。
- **口径**：所谓"逐字保留"只针对**文字**；标记仅在上述两处（标题层级、行首分隔线）改写，此外不做任何改动。剔除规则见「框架噪音清单」与「技能痕迹剔除」。

## 存储位置与回退

优先级：**用户显式指定的目标根目录** > **默认目标根目录 `~/Desktop`**。

归档批次的完整路径是 `<目标根目录>/dialogue-generation-file/<YYYYMMDD-HHMMSS>/`。注意这里只有**一层** `dialogue-generation-file`：`<目标根目录>` 本身指向上级目录，默认落盘结果是 `~/Desktop/dialogue-generation-file/<批次>/`。

- 目标根目录不存在时自动创建，含必要的父目录。
- 用户指定的根目录不可创建或不可写时，**回退到默认根目录 `~/Desktop`**，不得直接失败。
- 回退发生时必须在汇报里明确告知用户实际落盘位置。

## 归档批次与幂等

- 每个归档批次是一个以时间戳命名的独立目录，时间戳格式 `YYYYMMDD-HHMMSS`，取**执行时刻**（不是对话首条消息的时刻；让模型猜首条消息时间容易猜错，精度也不稳定）。
- **重跑产生新批次目录，旧批次原样保留**。产物是历史快照，覆盖属于不可逆的信息丢失。
- **不支持追加到已有批次**。刻意不支持，避免产出半新半旧的文件。

## 确认流程

- 落盘前**一次性问完两件事**：切分方案（主题清单、各主题涵盖范围、目标路径）与是否生成交接文档。询问交接时须说明其用途——**交接文档供新 agent 或新对话窗口承接上下文、继续工作**。用户确认后再写。
- **例外**：主题数 ≤2 时免去方案确认，但仍须询问是否生成交接文档（不得默认产出，也不得静默跳过询问）。
- 整理范围默认是整场对话；用户显式圈定时以用户为准。

## 显式不做

- 不引入脚本。归档是纯粹的模型动作，没有需要确定性复现的代码。
- 不做产物的增量更新或合并。
- 不改动三个固定文件名（`00_handoff.md` / `01_conclusions.md` / `02_raw_log.md`）。
- 不为主题切分引入兜底规则或长度阈值。
- 不为技能痕迹的判定引入确定性规则（与主题切分同理，属模型判断）。
