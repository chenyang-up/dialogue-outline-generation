# 设计决策与边界规则

本文件收纳本技能已锁定的决策与边界规则。`SKILL.md` 只保留执行骨架，细节在此。

## 两个动作

- **整理是必选动作**。交接是可选动作，整理完成后主动询问用户是否要产出，不得默认产出，也不得静默跳过询问。
- 交接文档**只引用净结论**，不含流水全文。理由：下游 agent 的上下文预算有限，流水全文会挤掉真正有用的信息。

## 主题切分

- **主题是文件内部的二级标题，不产生独立文件**。这是本技能最容易被误读的一条：当两个主题之间明确无逻辑关联时，是在同一个文件里另起一个主题节，而不是另建一个文档。
- **不设单文件字符上限硬兜底**。允许单个文档很长，接受由此带来的体积代价，换取语义完整性。
- 切分依据是语义相关性，由模型判断，**没有确定性算法**。因此切分结果不进入断言，只对产物结构做校验。

## 净结论分类

- 分类轴是**内容类型**，四类，顺序固定：`事实 → 决策 → 约束 → 待办`。顺序按逻辑依赖排——先说事实，再谈由事实导出的决策与约束，最后是待办。
- **「未决」是条目标记，不是类别**（行首 `[未决]`），可出现在任意类别下。之所以不把它做成类别：它描述的是"落定没落定"，属于**状态轴**，与内容类型轴正交；强行平级会让同一条信息在归属上二义。
- **判定问句**：
  - 事实 vs 约束——「这条是**查到的**还是**约定的**？」查到的 → 事实。
  - 决策 vs 约束——「**换个场景这条还成立吗？**」成立 → 约束；只针对当时那个问题 → 决策。
- **归入优先规则**：「跨类都拿不准时，**归入它一旦落定后所属的类别**」。这条是本分类能自洽的关键——没有它，悬而未决的**选择**（如"是否要支持追加到旧批次"）会被图省事地塞进「待办」，使该类退化成第二个"未决类"。按本规则，它一旦落定是"支持/不支持"的一次性选择，故归 `决策` + `[未决]`。
- **两级保留策略**：类别标题**按需保留**（无条目就不写）；主题标题**始终保留**（该主题无任何净结论时保留标题、正文写 `（本主题无净结论）`）。
- **空主题判据**：以"没有任何条目"为准，**统计时不区分条目是否带 `[未决]`**。

## 框架噪音清单

流水要"逐字保留对话正文"，但"对话"只指对话双方产生的内容。以下边界是锁定的。

### 剔除

- `<system-reminder>` 块（记忆与技能提醒、连接器状态、当前时间等）。
- 框架注入块：`<user-context>`、`<manually_attached_skills>`、`<project_context>`、`<team-project-context>` 等。
- 工具调用的机械返回，例如整份文件内容、目录列表。
- **模型的内部推理（thinking）**：它不是对话双方的输出，且原文通常冗长。

### 保留

- 用户消息全文。
- 模型正文全文，含代码块。
- **承载结论的工具结果退化为摘要保留**，例如构建报错、hook 失败原因、关键文件内容。这类信息往往正是本次对话的净结论所在，整体剔除会丢信息；原样保留又过于冗长，因此取摘要。

## 存储位置与回退

优先级：**用户显式指定的目标根目录** > **默认目标根目录 `~/Desktop`**。

归档批次的完整路径是 `<目标根目录>/dialogue-generation-file/<YYYYMMDD-HHMMSS>/`。注意这里只有**一层** `dialogue-generation-file`：`<目标根目录>` 本身指向上级目录，默认落盘结果是 `~/Desktop/dialogue-generation-file/<批次>/`。

- 目标根目录不存在时自动创建，含必要的父目录。
- 用户指定的根目录不可创建或不可写时，**回退到默认根目录 `~/Desktop`**，不得直接失败。
- 回退发生时必须在汇报里明确告知用户实际落盘位置。

## 归档批次与幂等

- 每个归档批次是一个以时间戳命名的独立目录，时间戳格式 `YYYYMMDD-HHMMSS`，取**执行时刻**（不是对话首条消息的时刻；让模型猜首条消息时间容易猜错，精度也不稳定）。
- **重跑产生新批次目录，旧批次原样保留**。产物是历史快照，覆盖属于不可逆的信息丢失。
- **不支持追加到已有批次**。刻意不支持，避免产出半新半旧的文件。

## 确认流程

- 落盘前展示切分方案：主题清单、各主题涵盖范围、目标路径。用户确认后再写。
- **例外**：主题数 ≤2 时免这道确认，避免简单情况也卡一轮交互。
- 整理范围默认是整场对话；用户显式圈定时以用户为准。
## 显式不做

- 不引入脚本。归档是纯粹的模型动作，没有需要确定性复现的代码。
- 不做产物的增量更新或合并。
- 不改动三个固定文件名（`00_handoff.md` / `01_conclusions.md` / `02_raw_log.md`）。
- 不为主题切分引入兜底规则或长度阈值。
